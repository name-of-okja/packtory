# packtory 대형 네트워크 규모 검증 설계 (하위 프로젝트 A)

작성일: 2026-09-27
상태: 승인됨, 구현 중 실측으로 고침 (2026-09-27)

## 1. 목적

지금의 데모는 2층·구간 4개의 한 줄짜리 라인이다. 실제 현장은 **5층, 층마다
수백 미터, 도시 교통처럼 여러 곳에서 물건이 들어와 합류·분기하는 네트워크**다.

이 하위 프로젝트는 그 규모에서 두 가지를 증명한다:

1. **읽힌다** — 신입이 전체보기에서 "어느 층 어느 구역이 문제인가" 를 바로 안다.
2. **버틴다** — 대형 씬 전체보기에서 30fps 이상.

그리고 그 규모를 **현실적으로 흉내내는 데이터**를 만든다: 막힘이 상류로
번지고, 막힌 곳 아래는 굶는 모의 데이터.

### 하위 프로젝트 B 와의 관계

고도화는 두 단계로 나눈다.

| | 내용 | 이 문서 |
|---|---|---|
| **A** | 대형 5층 네트워크 씬 + 전파 mock + 뷰어가 그 규모를 감당 | ✅ |
| **B** | 연결(그래프)을 스키마에 넣고, 빨간 구간 여럿 중 **진짜 원인**을 짚는다 | 별도 스펙 |

A 는 B 의 재료를 남긴다: 연결 추론 함수(`shared/graph.ts`)와, 원인이 알려진
채 연쇄 정체를 만드는 mock. B 는 이 mock 으로 "원인 판정이 맞는가" 를 시험한다.

## 2. 확정된 전제

| 항목 | 결정 | 근거 |
|---|---|---|
| 규모 | 5층, 층당 약 300×200m, 구간 400~500, 설비 약 300 | 지금 구조의 한계(라벨 전량 투영, 구간당 메시)가 드러나되 렌더링을 갈아엎지 않아도 되는 크기 |
| 씬 제작 | 시드 고정 생성기 | 500 구간은 손으로 못 쓴다 |
| 스키마 | **변경 없음** (`version: 3` 유지) | 연결 필드는 B 에서 넣는다 |
| 연결 | 끝점 일치로 추론 | 스키마·별도 파일 없이 mock 이 네트워크를 안다. 두 파일이 어긋날 일이 없다 |
| mock | 전파(back-pressure) + 시드 기반 의사난수 | 번지지 않는 500 구간은 데모에서 가짜처럼 보인다 |
| 판정 | `derive.ts` 는 한 가지만 고친다: 정지 시간을 out 이 멈춘 뒤와 물건이 들어차기 시작한 뒤 중 늦은 쪽부터 센다 | 쉬던 구간이 다시 받는 순간 빨강이 뜨는 가짜 경보를 대형 씬이 드러냈다 (5장). mock 은 여전히 원인만 만든다 |
| 층 보기 | 모드 A(적층)·B(계단), 버튼 하나로 전환 | 둘 다 필요. 초점 강조(C)는 뺀다 |
| 전체보기 밀도 | 정지만 + 구역 배지 | 6만 m² 급 층(300×200m)에서 신호등 하나는 점 하나다. 동네를 먼저 읽어야 한다 |

### 기존 원칙과의 관계

v3 스펙은 "층 선택 버튼 없음" 과 "카메라 각도 고정" 을 원칙으로 삼았다.
이번에 추가하는 버튼은 **층을 고르는 버튼이 아니라 배치를 바꾸는 버튼**이다 —
어느 모드에서든 다섯 층이 전부 한 화면에 보인다. 다만 각도 고정과 같은 위험
("누가 바꿔 놓고 가면 다음 사람이 이상한 화면을 본다")이 있으므로 모드는
저장하지 않고 스스로 기본값(A)으로 돌아온다 (6장).

바뀌지 않는 것: 허브의 어댑터 인터페이스·와이어 프로토콜·캐시·

## 4. 씬 생성기

### 공장의 모양

```
      1F 입고 도크 ×8 (서3·남5) ─┐          ┌─ 2F 연결 브리지 ×2 (옆 건물에서 유입)
                               ▼          ▼
  1F  입고 간선망 ──합류──▶ 상승 리프트 ×6 ─▶ 2F~5F 가공·보관 격자망
                                                   │ (분기 → 병렬 처리 → 합류)
  1F  출고 간선망 ◀──합류── 하강 리프트 ×6 ◀──────┘
        │
        ▼
      1F 출고 도크 ×4
```

- **격자 도로망.** 층마다 약 25m 간격의 가로·세로 도로 중 일부를 컨베이어로
  쓴다. 교차점이 합류·분기 지점이고, 구간 하나는 교차점 사이의 도로 조각이다.
  꺾이면 `via` 를 쓴다.
- **source** = 1층 입고 도크 8곳 + 2층 연결 브리지 2곳. **sink** = 1층 출고 도크 4곳.
- **층 역할.** 1층 입고·출고, 2~5층 가공·보관. 리프트는 1층에서 각 층으로
  여러 곳에서 오르내린다.
- 층 `elevation` 은 45m 간격 (모드 A 의 층 벌림, 6장).

### 불변식 (테스트가 확인한다)

| 조건 | 이유 |
|---|---|
| 순환 없음 (DAG) | 순환이 있으면 전파 mock 이 영구 교착할 수 있다. 순환 라인은 범위 밖이다 |
| 모든 구간은 어떤 source 에서 도달 가능하고 어떤 sink 에 도달 가능 | 막다른 구간은 영원히 꽉 차거나 비어 가짜 빨강·회색을 만든다 |
| 합류·분기 차수 ≤ 3 | 현실적인 머지기·분류기 |
| 이어지는 구간의 끝점 좌표가 **정확히 같다** | 연결 추론(5장)이 이것에 매달린다 |
| `validateScene` 에러 0 | 부팅 검증을 그대로 통과해야 한다 |
| 같은 시드 → 바이트 단위로 같은 출력 | 재현성 |
| 구간 수 400~500, 설비 250~350, 층 5 | 규모 목표 |

### 채우는 것

- **구역**: 층마다 약 100×100m 를 3×2 로, 총 30개. 라벨 "3층 B구역".
- **설비**: 합류점에 머지기, 분기점에 분류기, 일부 구간 중간에 가공 설비.
  일부에만 `warn` 이 있는 태그를 단다. 설비는 반드시 자기 구역 안에 둔다.
- **카메라**: 구역마다 0~1대. `stream` 은 `go2rtc.yaml` 의 기존 세 이름
  (`cam-in-1`, `cam-fill-1`, `cam-fill-2`) 을 돌려 쓴다 — go2rtc 는 안 바꾼다.
- **id / 라벨**: id 는 `f3-c041`, 라벨은 "3층 B-41 이송". 리프트는 `lift-u03`
  / "상승 리프트 3".
- **capacity**: 컨베이어는 길이에 비례(미터당 약 0.5개, 최소 4), 리프트 4.

### 실행과 산출물

```bash
npx tsx tools/gen-scene.ts --seed 1 > scene.large.json
SCENE=../scene.large.json npm start   # hub/ 에서
```

`scene.large.json` 은 커밋한다 — 생성기를 돌리지 않고도 띄울 수 있어야 한다.
새 의존성은 없다 (`tsx` 는 hub 에 이미 있다).

### 작은 `scene.json`

그대로 둔다 — 손으로 고치는 예제이고 빠른 확인용이다. 다만 **끝점을 이어
붙여** 체인(`conv-1 → lift-1 → conv-3 → conv-5`)으로 만든다. 선이 설비를
관통해도 괜찮다 — 컨베이어는 원래 설비를 지나간다. 이 수정은 리팩터링(1)
확인이 끝난 뒤에 한다 — 먼저 고치면 전후 스크린샷 비교가 무의미해진다.

## 5. 연결 추론과 전파 mock

### 연결 추론 (`shared/graph.ts`)

```ts
/** 구간 id → 하류 구간 id 들. 끝점 키 `층:x:y` 가 같으면 이어진 것이다 */
export function downstream(scene: Scene): Map<string, string[]>
```

- X 의 `to` 키 = Y 의 `from` 키 → X → Y. 리프트는 `to` 가 다른 층에 있을
  뿐이라 따로 다루지 않는다.
- 하류가 없으면 sink, 상류가 없으면 source.
- 좌표는 숫자를 그대로 문자열로 만든 키로 비교한다. 생성기는 정수 미터만
  찍으므로 부동소수 오차가 끼지 않는다.

### 전파 mock — 매 틱(100ms)을 25ms 네 단계로

1. **이동.** 구간은 안에 물건이 있고(지나는 시간이 다 된 것만) 하류 중 하나에
   빈자리(`wip < capacity`)가 있을 때만 하나를 내보낸다. 속도 상한은 구간의
   처리 속도 `r`. 분기는 자기 몫보다 뒤처진 하류부터, 합류는 빈자리가 나는 대로
   받는다. sink 는 늘 내보낼 수 있다. **위상 역순으로(하류부터)** 처리해 같은
   단계 안에 빈자리가 전파되게 한다. 틱을 단계로 쪼개는 것은 짧은 구간이 초당
   capacity×10 개에서 막히지 않게 하기 위해서다 (실측: 1F 출고 분배선에서 망 전체가 섰다).
2. **정상 유량.** 구간마다 "source → 그 구간 → sink" 경로 하나(이웃은 가장 덜 쓰인
   쪽)에 0.2개/s 를 흘려 더한 것이 그 구간의 정상 유량이다. 경로 합이라 모든
   합류·분기점에서 들어온 양 = 나간 양이 저절로 맞고, 모든 구간이 0.2개/s 이상
   흐른다. 처리 속도 `r` = 유량 / **0.7**. 여유 30% 가 막힘 해제 뒤 적체를 스스로
   빼낸다 — 그래서 기존 `DRAIN_FACTOR` 는 지운다. (분기를 균등 분배하면 뒤로 갈수록
   유량이 기하급수로 줄어 천 배 넘게 차이 났다 — 실측.)
3. **워밍업.** 만들 때 2분을 미리 돌린다. 빈 공장에서 시작하면 물건이 안 닿은
   구간이 1분 남짓 줄줄이 idle 로 보인다.
4. **막힘 (빨강의 원인).** 120초 주기마다 구간 150개당 1곳(최소 1곳)을 골라
   `out` 을 멈춘다. 위치·시작 시점·지속 시간(30~90초)은 주기마다 새로 뽑는다.
   후보는 상류가 2단계 이상인 구간 — 적체가 거슬러 번지는 모습이 보여야 한다.
5. **도크 휴무 (회색의 원인).** source 마다 시드로 정한 "트럭 없음" 시간대가
   있고, 주기마다 조금씩 흔들린다. 그동안 유입이 없다. 그 source 에서만 받는
   하류가 비어 `idle` 이 된다. 기존 `STARVE_PLAN` 은 지운다 — 억지 각본을
   현실적인 원인이 대신한다.

결과: 막힌 구간이 참 → 상류가 차례로 **빨강** → 막힌 곳에서만 받는 하류는
**회색** → 합류점 아래는 다른 갈래 덕에 **초록**.

### 랜덤성

**시드 기반 의사난수.** 보는 사람에게는 무작위, 같은 시드면 같은 재생.

| 랜덤인 것 | 범위 |
|---|---|
| 막힘 위치·시작·지속 | 위 4번 |
| 도크 휴무 시간대 | 위 5번 |
| 구간별 처리 속도 | `r` 의 ±10% (시작할 때 한 번) |
| 설비 태그 값의 잡음 | 기존 `Math.random` 을 같은 난수원으로 교체 |

- 시드는 `MOCK_SEED` 환경 변수, 기본값 1. 테스트는 시드를 직접 넘긴다.
- 생성기 시드(공장 모양)와 mock 시드(사건 순서)는 별개다 — 같은 공장의 다른
  하루를 재생할 수 있다.
- **랜덤만으로는 빨강이 절대 나오면 안 된다.** 부하 70% + 속도 ±10% 는 상한
  안에 머문다. 빨강은 막힘에서만 나온다 — 빨강이 흔해지면 아무도 화면을 안 본다.

### 바뀌지 않는 것

태그 이름(`{id}.in`/`{id}.out`), `counterMax` 랩어라운드, 설비 태그 생성 방식.
mock 이 쓰는 것은 여전히 카운터뿐이다.

`derive.ts` 는 정지 시간 기준만 고친다 — `max(out 이 멈춘 시각, 물건이 들어차기
시작한 시각)`. 비어 쉬던 구간에 물건 하나가 다시 들어온 순간을 막힘으로 보던
가짜 경보다 (도크 휴무를 켠 대형 씬 10분에서 가짜 stalled 9 구간 — 실측).

## 6. 뷰어

### 층 배치 함수 (`shared/layout.ts`)

```ts
export type LayoutMode = "stack" | "stair"
/** 층의 월드 원점. 모든 지오메트리·라벨·피킹·flyTo 가 이것만 거친다 */
export function floorOrigin(scene: Scene, floorId: string, mode: LayoutMode): { dx: number; dy: number; elev: number }
```

| 모드 | `dx` | `dy` | `elev` |
|---|---|---|---|
| A `stack` (기본) | 0 | 0 | `floorElevation(scene, floorId)` — 기존 데이터 손잡이 그대로 |
| B `stair` | `−r × (층 가로폭 + 20m)` | `+r × (층 가로폭 + 20m)` | `r × 10m` |

`r` 은 order 의 정렬 순위다 (order 0 인 지하층·번호 건너뜀에도 음수로 안 밀린다).
(−x, +y) 는 기본 시점에서 화면 오른쪽이라 1층부터 왼쪽→오른쪽으로 선다 — +x 로
밀면 위층일수록 화면 아래로 내려갔다(실측). 전체보기 배율은 투영된 화면 세로·가로
폭을 둘 다 따진다.

층 가로폭 = 모든 층 구역 rect 의 X 범위 중 최댓값. `shared/` 에 두는 것은
순수 함수라 hub 의 `node --test` 로 시험하기 위해서다.

`toBabylon`·`segmentPoints`·`sceneBounds`·`build`·`andon`·`flow`·`Labels` 가
전부 `floorOrigin` 을 거친다. 지금 흩어진 `floorElevation()` 직접 호출(`build.ts`
×2, `andon.ts`, `Labels.tsx`, `coords.ts`)은 남지 않는다.

리프트는 지금처럼 출발점의 세로 기둥 + 도착 층 가로 구간이다. B 에서는 그
가로 구간이 층 사이 틈을 건너는 선이 된다 — 받아들인 비용이다.

- 누르면 뷰어 메시(정적·신호등·흐름·피킹)를 전부 버리고 새 모드로 다시 짓고,
  새 bounds 로 카메라를 home 으로 보낸다. 전환 애니메이션은 없다.
- 모드는 저장하지 않는다. 새로고침하면, 또는 **포인터·키 조작 없이 5분**이
  지나면 A 로 돌아간다.

### 밀도 제어

기준은 기존 줌 문턱 `SHOW_BELOW` 하나다.

| | 멀리 (`zoom ≥ SHOW_BELOW`) | 가까이 |
|---|---|---|
| 구간 선 | 전부 (색으로 상태) | 전부 |
| 신호등 | **stalled 만** | 전부 |
| 구간·설비 라벨 | **stalled 구간만** | 화면 안의 것만 |
| 구역 배지 | **보인다** | 숨는다 |

- 구역 배지: "3층 B구역 · 정지 2" (빨강) / "3층 B구역 · 정상" (초록). 구역의
  구간 중 stalled 개수를 센다. HTML 오버레이로, 기존 라벨 투영을 그대로 쓴다.
- 배지를 누르면 그 구역 중심으로 `flyTo` 한다.
- 라벨은 **화면 밖이면 투영 결과를 버리고 DOM 에 넣지 않는다.**

### AlertBar

- 전파 때문에 막힘 하나가 빨강 여럿이 된다. 칩은 **5개까지**, 나머지는
  "외 N건" 하나로 묶는다.
- 정렬은 그대로 정지 시간 긴 순. 처음 막힌 곳이 가장 오래 멈춰 있으므로
  대개 원인이 맨 앞에 온다 — 우연히 맞는 것이지 보장이 아니다. 보장은 B 의 일이다.

### 성능

- 목표: `scene.large.json` 전체보기 **30fps 이상** (내장 GPU 노트북).
- URL 에 `?fps` 를 붙이면 구석에 `engine.getFps()` 를 띄운다. 사람이 재고
  README 에 "번들 크기" 절처럼 기록한다.
- **미달하면 거기서 멈추고 따로 결정한다.** 정적 메시를 병합하면 구간별 피킹이
  깨지므로 방법을 미리 정할 수 없다.
- 번들 목표 gzip 350KB 유지. 새 Babylon 모듈을 들이지 않는다.

## 7. 테스트

### 자동 (hub, `node --test`)

| 대상 | 확인 |
|---|---|
| `floorOrigin` | A 는 `dx=0`, `elev=floorElevation`. B 는 층 순서대로 `dx`·`elev` 증가, 층끼리 X 범위가 겹치지 않음 |
| `downstream` | 끝점 일치 → 연결, 불일치 → 없음, 리프트 층 넘김, 합류·분기 |
| 생성기 | 4장 불변식 전부 (DAG, 도달성, 차수, 끝점 일치, `validateScene` 0 에러, 결정성, 규모) |
| 전파 mock (시계를 직접 돌림) | ① 막힘 없이 10분 → stalled 0 ② 한 구간 막음 → 직상류 stalled, 전용 하류 idle ③ 해제 → 다음 막힘 전에 전부 running ④ 보존: 유입 총량 = 유출 총량 + 전체 WIP ⑤ 같은 시드 → 같은 카운터 열 |

기존 `mock.test.ts` 에서 `conv-3` 을 직접 가리키던 테스트는 위로 교체한다.
`derive.test.ts`·`scene.test.ts`·`fanout.test.ts` 는 그대로 통과해야 한다.

### 사람 (`docs/BROWSER-CHECKLIST.md` 에 추가)

1. 리팩터링 전후 작은 씬 스크린샷이 같다 (`tools/shot.mjs`).
2. 대형 씬이 뜨고 다섯 층이 A 에서 벌어져 보인다.
3. 버튼으로 B 전환 → 층이 계단으로 겹침 없이 보인다 → 다시 A.
4. B 에서 5분 방치 → A 로 돌아온다.
5. 멀리서: 신호등·라벨은 정지 구간만, 구역 배지 30개.
6. 배지 클릭 → 그 구역으로 날아가고 배지가 숨고 라벨이 나온다.
7. 막힘이 생기면 상류로 빨강이 번지고, 하류 일부가 회색이 된다.
8. AlertBar 칩 5개 + "외 N건".
9. `?fps` 로 30fps 이상.
