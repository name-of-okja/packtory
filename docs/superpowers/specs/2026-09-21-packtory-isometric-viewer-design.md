# packtory 아이소메트릭 뷰어 설계

작성일: 2026-09-21
상태: 초안 (검토 대기)

## 1. 목적

신입 시설 관리·유지보수 담당자가 화면을 처음 봐도 **지금 라인이 도는지,
안 돌면 어디가 막혔는지**를 한 눈에 알 수 있게 한다.

공장을 **비스듬히 내려다보는 입체 뷰**로 그리고, 층을 동시에 보여주고,
막힌 구간 위에 **적층 신호등**을 세우고, 그 구간을 클릭하면 해당 구역
CCTV를 모달로 보여준다.

화면은 **어디서 멈췄는지**까지 답한다. **왜 멈췄는지**는 사람이 CCTV를
보고 판단한다.

## 2. 기존 스펙과의 관계

이 문서는 `2026-09-19-packtory-flow-monitor-design.md` (v2) 를 **대체한다.**

v2 는 위에서 수직으로 내려다보는 평면도에 층 선택 탭이었다. 실제로 만들어
보여드린 뒤 "생각한 제품과 아예 다르다" 는 답을 받았고, 참조 이미지
(아이소메트릭 공장 일러스트, Siemens Intosite) 로 간극이 드러났다.

### 무엇을 잘못 읽었나

| v2 에서 들은 말 | v2 가 만든 것 | 실제로 원한 것 |
|---|---|---|
| "네이버지도 같은 느낌으로 2.5D" | 위에서 수직으로 보는 평면도 | **아이소메트릭** — 부피가 보이는 비스듬한 입체 |
| "z축으로 층 개념도 존재할 수 있다" | 층 선택 탭 (한 번에 한 층) | **층이 동시에 보인다** |

"2.5D" 를 평면도로, "층 개념" 을 탭으로 읽은 것이 원인이다. 둘 다 그럴듯한
독해였지만 둘 다 틀렸고, **화면을 만들어 보여주기 전까지 드러나지 않았다.**

### 뒤집힌 결정

| v2 | 이 스펙 | 이유 |
|---|---|---|
| SVG 평면도 | Babylon.js + 정사영 카메라 | 부피와 층을 동시에 보여주려면 깊이가 필요하다 |
| 층 선택 탭 | 층을 실제 높이에 쌓아 동시 표시 | 버튼으로 갈아끼우면 "한 화면에 전체" 가 아니다 |
| 구간 = 빨강 점선 + 깜빡임 | 구간 끝의 적층 신호등 | 평면 색칠은 3D 에서 각도에 따라 가려진다 |
| 글자를 SVG `<text>` 로 | HTML 오버레이 | 3D 텍스처의 한글은 흐리다 |

### 유지된 결정

**허브는 한 줄도 바뀌지 않는다.** 어댑터 인터페이스, 와이어 프로토콜,
정지 판정(`derive`), 캐시, 팬아웃, 정적 서빙, 테스트 37개가 전부 그대로다.
렌더링만 바뀌는 일이다.

그리고 제품의 뼈대도 그대로다:

- **판정은 서버, 그림은 클라이언트.** 갓 접속한 브라우저는 과거 카운터가
  없어 "3분째 정지" 를 계산할 수 없다.
- **`stalled`(꽉 찬 채 멈춤 = 사고)와 `idle`(텅 빈 채 멈춤 = 정상)의 구분이
  이 제품의 값어치다.** 뭉개면 빨강이 흔해지고, 흔해지면 아무도 화면을
  안 본다.
- 읽기 전용, 모의 데이터, H.264 전용, 영상은 허브를 통과하지 않는다.

### 웹 클라이언트는 새로 쓴다

v2 의 `Map.tsx`/`geom.ts`/`Segment.tsx`/`FloorTabs.tsx` 는 SVG 전제로
지어졌고 3D 로 옮길 것이 없다. `AlertBar`/`Modal`/`useValues` 의 **동작**은
그대로 살지만 3D 맥락에 맞게 다시 짠다.

## 3. 확정된 전제

| 항목 | 결정 | 근거 |
|---|---|---|
| 렌더링 | Babylon.js, `ArcRotateCamera` 를 정사영 모드로 | 확장 경로의 glTF 에셋 카탈로그가 내장이다. Three.js 면 로더를 따로 붙여야 한다 |
| 카메라 각도 | 고정 (수평에서 35.26° 올려다본 각, 방위각 45°씩 네 모서리) | 자유 회전은 "각도를 맞춰야 보이는" 화면을 만든다 — 신입이 제일 못 하는 일 |
| 모델 범위 | 설비 + 층 바닥판. 벽·지붕 없음 | 감시하려는 것을 가리는 게 하나도 없어야 한다 |
| 층 간격 | 씬의 `floor.elevation` | 코드는 하나, 현장마다 데이터로 조절. UI 손잡이가 안 늘어난다 |
| 상태 표현 | 구간 끝의 적층 신호등 | 기둥은 위에서도 옆에서도 다른 설비 뒤에서도 보인다. 현장에서 이미 쓰는 언어다 |
| 글자 | HTML 오버레이 (3D 좌표를 화면 좌표로 투영) | 한글 선명도 + Babylon GUI 모듈 회피 |
| 허브 | 변경 없음 | 렌더링과 무관하다 |

### 새 필드

| 필드 | 뜻 | 기본값 |
|---|---|---|
| `floors[].elevation` | 그 층 바닥의 높이 (미터) | `(order - 1) × 6` |
| `equipment[].height` | 설비 높이 (미터) | `2` |
| `equipment[].shape` | `"box"` 또는 `"cylinder"` | `"box"` |

셋 다 선택 필드다. **기존 v2 씬을 한 글자도 안 고쳐도 뜬다** — `version` 만
3 으로 올리면 된다.

`elevation` 이 층 겹침의 유일한 손잡이다. 실제 층고(4~6m)를 넣으면 진짜
건물처럼 보이고, 12m 를 넣으면 벌어져서 각 층이 다 보인다. 층이 5개인
현장이면 데이터에서 벌린다.

### 좌표계

씬 좌표는 평면도 기준으로 **X는 오른쪽, Y는 위쪽**, 단위는 미터다 (v2 와
동일).

Babylon 은 Y축이 위쪽인 3차원이므로 매핑은 이렇게 된다:

```
씬 (x, y) + 층 elevation  →  Babylon (x, elevation, y)
```

즉 **씬의 Y가 Babylon 의 Z가 된다.** v2 에서 SVG 의 Y축이 아래쪽이라
뒤집어야 했던 문제가 사라진다 — 뒤집는 곳이 없으니 뒤집힌 곳을 찾을 일도
없다.

컨베이어 벨트면은 바닥판 위 **0.8m** 에 놓는다 (상수, 씬 필드가 아니다).

### 씬 검증

v2 의 6규칙을 그대로 유지하고 두 가지를 더한다:

7. `floors[].elevation` 이 있으면 `order` 순으로 단조 증가할 것
8. `equipment[].height` 가 양수이고, 위층 `elevation` 을 넘지 않을 것
   (넘으면 설비가 위층 바닥을 뚫는다) — **경고**, 에러 아님

## 6. 클라이언트

Vite + React + TypeScript + Babylon.js.

React 는 **오버레이 UI만** 담당한다 — 이상 칩, 모달, 카메라 조작 버튼,
3D 위에 얹히는 글자. Babylon 씬은 `useEffect` 안에서 명령형으로
생성·정리한다. 선언형 래퍼를 쓰지 않는다.

```
web/src/
  main.tsx
  App.tsx           상태 보유 (selection, 카메라 이동 요청)
  scene.ts          GET /api/scene
  useValues.ts      WS 훅 (3초 재접속, 스냅샷 시 전체 교체)
  viewer/
    Viewer.tsx      Babylon 엔진·씬 수명주기, React 경계
    camera.ts       정사영 ArcRotateCamera, 각도 스냅, 이동
    build.ts        씬 JSON → 메시 (바닥판·설비·구간·리프트)
    andon.ts        적층 신호등 메시와 상태 반영
    flow.ts         Thin Instance 물건 흐름
    pick.ts         클릭 → Selection (우선순위 규칙)
    project.ts      3D 좌표 → 화면 좌표 (오버레이용)
  Labels.tsx        HTML 오버레이 라벨
  AlertBar.tsx      상단 이상 칩
  Modal.tsx         CCTV + 수치
  state.ts          segState/segWip/segStallMs/formatStall/STATE_LABEL
  styles.css
```

### Babylon import 규율

`import * as BABYLON from "babylonjs"` 를 쓰면 400KB 가 통째로 들어온다.
`@babylonjs/core` 에서 개별 import 해서 트리셰이킹을 건다:

```ts
import { Engine } from "@babylonjs/core/Engines/engine"
import { Scene } from "@babylonjs/core/scene"
import { ArcRotateCamera } from "@babylonjs/core/Cameras/arcRotateCamera"
```

번들 목표는 gzip **250KB 이하**다. 넘으면 무엇이 들어왔는지 찾는다.

### 카메라

```
종류      ArcRotateCamera, mode = ORTHOGRAPHIC_CAMERA
고도각    beta = 0.9553 rad — 고정, 바꿀 수 없다
          Babylon 의 beta 는 +Y 축에서 재므로 54.74°,
          수평에서 재면 35.26° 다. 진짜 아이소메트릭(1:1:1) 각이다.
방위각    alpha ∈ {45°, 135°, 225°, 315°} — 네 모서리
줌        orthoLeft/Right/Top/Bottom 을 한 배율값과 화면 비율로 계산
```

| 조작 | 동작 |
|---|---|
| 드래그 | 팬 (target 이동) |
| 휠 | 줌 |
| `⟲` `⟳` | 90°씩 회전, 200ms 보간 |
| `⌂` | 전체보기 — 모든 층을 담는 바운딩박스에 맞춤 |

**기울기는 바꿀 수 없다.** 일부러다. 기울일 수 있으면 누군가 기울여 놓고
가고, 다음 사람이 이상한 화면을 본다.

### 지오메트리

| 씬 요소 | 메시 | 재질 |
|---|---|---|
| 구역 (`section.rect`) | 얇은 바닥판 (두께 0.1m) | 반투명 (alpha 0.25), 구역색 |
| 설비 `shape: "box"` | 상자 `size × height` | 불투명 회색 |
| 설비 `shape: "cylinder"` | 원통 (지름 = `size[0]`) | 불투명 회색 |
| 구간 (평면) | 폴리라인을 따라 난 얇은 상자 (벨트) | 상태색 |
| 구간 (리프트) | 두 층을 잇는 세로 기둥 | 상태색 |
| 신호등 | 기둥 + 램프 구 | 상태색, `emissive` |

바닥판은 위층이 아래층을 가리지 않도록 반투명이다.

### 적층 신호등 (Andon)

각 구간의 **출구 끝**에 세운다. 막힘이 드러나는 자리가 거기다.

```
기둥 높이  max(3m, 그 구간이 닿는 설비 높이 + 1m) — 뒤에 서도 보인다
램프       구, 반지름 0.35m, emissive
위치       segment.to 지점, 층 elevation 기준
```

| 상태 | 램프 | 점멸 |
|---|---|---|
| `running` | 초록 | 없음 |
| `stalled` | **빨강** | **1Hz** |
| `idle` | 꺼짐 (어두운 회색) | 없음 |
| `unknown` | 흰색 | 0.5Hz |

**기둥이라 각도에 안 가린다.** 평면 색칠은 3D 에서 카메라 각도에 따라
사라지지만 수직 요소는 어느 모서리에서 봐도 보인다. 그리고 현장 사람이
이미 읽을 줄 아는 물건이다.

### 정지와 대기를 가르는 두 채널

|  | 신호등 | 컨베이어 위 |
|---|---|---|
| 가동 | 초록 | 물건이 흐른다 |
| **정지** | **빨강 + 점멸** | **물건이 꽉 찬 채 멈춰 있다** |
| 대기 | 꺼짐 | 비어 있다 |
| 불명 | 흰색 깜빡임 | 물건 없음 + 회색 벨트 |

**색만으로 가르지 않는다.** 정지는 "빨강" 이 아니라 "빨강 + 꽉 참" 이고,
대기는 "회색" 이 아니라 "꺼짐 + 비어 있음" 이다. 색을 전부 빼도 물건이
있느냐 없느냐로 갈린다.

장비 경고(`warn` 초과)는 **다른 언어를 쓴다** — `HighlightLayer` 로 설비
외곽에 주황 발광. 신호등과 모양도 위치도 달라서 겹쳐 봐도 안 헷갈린다.

### 물건 흐름

Babylon 의 **Thin Instance** 로 그린다. 상자 하나를 수백 개 복제해도
드로우콜이 하나다.

```
개수     = min(wip, capacity)
위치     = 구간 폴리라인을 따라 고정 속도 (3 m/s 상당)
갱신     = 렌더 루프에서 행렬 버퍼 갱신
정지 시 = 갱신을 멈춘다 → 그 자리에 얼어붙는다
```

`capacity` 를 넘겨 그리지 않는 규칙은 v2 에서 온 것이다. 간격이
`경로길이 / capacity` 로 고정이므로 그 이상은 앞선 물건과 겹쳐서 보이지
않는다. 넘는 수량은 `+N` 라벨이 말한다.

### 클릭

`scene.multiPick` 으로 광선에 걸린 것을 전부 받은 뒤 **종류 우선순위**로
고른다:

```
설비 > 구간·리프트 > 신호등(= 그 구간) > 구역 바닥판
같은 종류면 카메라에 가까운 것
```

바닥판을 맨 뒤에 두는 이유는, 반투명 바닥 너머의 아래층 설비를 곧장 누를 수
있어야 하기 때문이다. 바닥판 자체도 클릭 대상이므로(구역 모달) `isPickable`
을 끄지는 않는다.

**팬 드래그 뒤의 합성 클릭은 막는다.** 포인터가 4 CSS 픽셀 넘게 움직였으면
클릭을 무시한다. v2 에서 같은 결함을 겪었다.

### HTML 오버레이 라벨

설비 이름, 구간 이름, `+N` 초과 수량, 정지 경과 시간은 3D 로 그리지 않는다.
`Vector3.Project` 로 화면 좌표를 구해 그 위치에 `<div>` 를 얹는다.

- 한글이 3D 텍스처로는 흐리다
- Babylon GUI 모듈을 안 들여도 된다
- CSS 를 그대로 쓴다

라벨은 **줌 배율이 일정 이상일 때만** 뜬다. 멀리서 보면 신호등만 남는다.

### 이상 칩

`state === "stalled"` 인 구간만 상단에 칩으로 띄운다. 정지 시간이 긴 순서.
전부 정상이면 "정상 가동" 한 줄.

**칩을 누르면 카메라가 그 구간으로 이동한다** (층 전환이 아니라 팬+줌,
400ms 보간). 층 탭이 없으니 전환할 것이 없다.

살아있는 영역(`aria-live`)은 칩과 분리한다 — 정지 시간이 초마다 바뀌는데
같이 두면 스크린리더가 그때마다 막대 전체를 다시 읽는다. 별도 숨은 영역이
**정지 구간 집합이 바뀐 순간에만** 말한다.

### 모달

대상이 구역이든 설비든 구간이든 **같은 모달**이고 내용만 다르다. CCTV 는
언제나 그 대상이 속한 구역에서 온다. 카메라가 여러 대면 탭, 활성 탭 하나만
재생한다. 모달을 닫으면 스트림을 끊는다.

초점은 열릴 때 모달 안으로 가고 닫힐 때 원래 자리로 돌아온다. Tab 이 모달
밖으로 나가지 않는다.

### 성능

- 물건은 Thin Instance — 드로우콜 1
- 신호등 점멸은 재질의 `emissiveColor` 만 바꾼다 (메시 재생성 없음)
- React 는 값 갱신 주기로만 리렌더하고, 3D 갱신은 Babylon 렌더 루프에서
  직접 한다 — React 가 프레임마다 도는 일은 없다
- `prefers-reduced-motion` 이면 물건 이동과 신호등 점멸을 멈춘다. 색·개수는
  그대로라 정보가 사라지지 않는다

## 9. 완료 기준

1. 접속하면 부지 전체가 한 화면에 들어오고, 층이 동시에 보인다
2. 가동 중인 구간에 물건이 흐르고 신호등이 초록이다
3. 모의 어댑터가 `conv-3.out` 을 멈추면 → `stallSec` 뒤 그 구간 신호등이
   빨강으로 점멸하고, 물건이 꽉 찬 채 얼어붙는다
4. 상단에 `충전부 충전 이송 정지 0:12` 칩이 뜨고 초가 올라간다
5. **카메라를 움직이지 않아도 다른 층 신호등이 빨개지는 것이 보인다**
6. 칩을 누르면 카메라가 그 구간으로 이동한다
7. 구간을 클릭하면 `in`/`out`/`wip`/정지시간과 그 구역 CCTV 라이브가 뜬다
   (지연 1초 미만)
8. **굶어서 비워진 구간은 신호등이 꺼진 채 비어 있고, 칩이 뜨지 않는다.
   정지 구간과 나란히 한 화면에 보인다**
9. **브라우저를 새로 열어도 정지 시간이 이어서 맞게 나온다**
10. 리프트가 층 사이 세로 기둥으로 보이고, 클릭하면 모달이 뜬다
11. 허브를 재시작하면 클라이언트가 자동 재접속하고 스냅샷을 다시 받는다

**8번과 9번이 이 설계의 시험지다.** 8번이 깨지면 빨강이 흔해져 아무도 안
보고, 9번이 깨지면 화면이 거짓말을 한다.

v2 의 기준 5(다른 층 탭이 빨개진다)와 10(리프트 클릭 시 층 전환)은
사라졌다 — 층이 동시에 보이면서 **UI 장치 없이 그냥 성립하게 됐다.**

## 11. 확장 경로

순서대로. 각 단계는 앞 단계의 인터페이스를 바꾸지 않는다.

1. **glTF 에셋 카탈로그** — `shape` 필드에 파일명을 허용. Babylon 에
   로더가 내장이라 상자·원통을 실제 설비 모델로 바꾸는 데 새 의존성이
   없다
2. **실제 어댑터** — `OpcUaAdapter` 를 `Adapter` 인터페이스로 구현.
   허브·클라이언트 무변경
3. **씬 에디터** — 3D 에서 기즈모로 배치, 씬 JSON 저장
4. **벽·건물 외피** — 씬에 벽 선분을 더하고 지붕은 생략해 안을 본다
5. **정지 이력** — `stallMs` 시계열 적재. 가동률 집계의 전제
6. **다중 카메라 타일** — 가시성 기반 재생 제어 정책 필요
