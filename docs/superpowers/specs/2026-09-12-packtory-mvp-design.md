# packtory MVP 설계

작성일: 2026-09-12
상태: 초안 (검토 대기)

## 1. 목적

판매용 데모. 3D 공장 씬에서 장비를 클릭하면 해당 장비의 실시간 값과
CCTV 라이브 영상이 함께 뜨는 것을 보여준다.

핵심 주장은 **"3D 안에서 데이터와 영상을 동시에 본다"** 이고,
그중 경쟁 제품 대비 차별화 지점은 **저지연 라이브 영상**이다.

업종을 특정하지 않는 공통 플랫폼을 지향한다.

## 2. 확정된 전제

| 항목 | 결정 | 근거 |
|---|---|---|
| 카메라 코덱 | H.264 전용 | 무변환 통과. H.265는 트랜스코딩 필요하므로 MVP 제외 |
| 데이터 소스 | 모의 생성기 | 실제 프로토콜 연결은 계약 후. 단 어댑터 인터페이스는 실제와 동일 |
| 제어 | 읽기 전용 | 쓰기는 안전·권한·감사로그를 동반하는 별도 제품 |
| 클라이언트 | 웹 (Babylon.js) | 자동화 모니터링에 웹으로 충분. Unity WebGL은 로딩 수십 MB, CAD 임포트가 요구사항이 아님 |
| 씬 구성 | JSON 직접 편집 | 에디터는 축(씬 모델)이 검증된 뒤에 만든다 |

## 3. 아키텍처

```
외부 시스템            중개서버 (packtory-hub)          클라이언트
──────────            ───────────────────────          ──────────
OPC-UA   ─┐                                           ┌─ 웹 (Babylon.js)
MQTT     ─┼→ 어댑터 → 정규화 → WebSocket 팬아웃 ───────┼─ (나중에 뭐든)
REST     ─┤          (우리 형태)                       └─
모의생성기─┘

CCTV ─────→ go2rtc ────────────── WebRTC ──────────────→ 브라우저 직결
```

**비디오는 중개서버를 통과하지 않는다.** 게이트웨이에서 브라우저로 직접
간다. 서버가 영상 바이트를 중계하면 CPU와 대역폭이 카메라 수만큼 곱해진다.
중개서버는 카메라 스트림의 주소만 알려준다.

중개서버와 go2rtc는 같은 장비에 함께 배치한다. 둘 다 OT망에서
카메라·PLC에 닿아야 하고, 클라이언트는 사무망에서 접속한다.

## 4. 씬 모델 (1차 축)

전체 시스템이 이 스키마에 매달린다. 클라이언트·서버·에디터가 모두 이것만
공유한다.

```json
{
  "version": 1,
  "name": "데모 라인",
  "equipment": [
    {
      "id": "filler-1",
      "label": "충전기 1",
      "asset": "box",
      "position": [0, 0, 0],
      "rotation": 0,
      "scale": [2, 3, 2],
      "tags": [
        { "key": "speed", "label": "속도", "unit": "bpm", "warn": 250 },
        { "key": "temp",  "label": "온도", "unit": "°C",  "warn": 80  }
      ],
      "cameras": ["cam1"]
    }
  ],
  "cameras": [
    { "id": "cam1", "label": "충전기 상부", "stream": "cam1" }
  ]
}
```

규칙:

- 전역 태그 식별자는 `"{equipment.id}.{tag.key}"` 이다. 예: `filler-1.speed`
- `camera.stream` 은 `go2rtc.yaml` 의 스트림 이름과 **문자 그대로 같다.**
  별도 매핑 테이블을 두지 않는다.
- `asset` 은 MVP에서 `"box" | "cylinder" | "plane"` 세 가지.
  glTF 카탈로그는 확장 단계에서 같은 필드에 파일명을 넣는 방식으로 확장한다.
- `rotation` 은 Y축 회전(라디안) 단일 값. 3축 회전은 필요해질 때 배열로 확장.
- `warn` 은 선택 필드. 있으면 임계, 없으면 상태 판정에서 제외.

## 5. 와이어 프로토콜 (2차 축)

씬 모델 다음으로 중요한 인터페이스. 어댑터가 무엇이든 클라이언트는 이것만
본다.

### HTTP

`GET /api/scene`

```json
{
  "scene": { "...4장의 씬 문서..." },
  "go2rtcBase": "http://192.168.0.10:1984"
}
```

클라이언트는 `go2rtcBase` 와 `camera.stream` 을 조합해 영상 주소를 만든다.
엔드포인트는 이것 하나뿐이다.

### WebSocket

`GET /ws` 로 업그레이드. 클라이언트는 아무것도 보내지 않는다 (읽기 전용).

접속 직후 스냅샷 1회:

```json
{ "type": "snapshot", "data": [
  { "tag": "filler-1.speed", "v": 247, "ts": 1757649600000, "q": "good" }
]}
```

이후 변경분만 푸시 (100ms 간격으로 배치):

```json
{ "type": "values", "data": [
  { "tag": "filler-1.speed", "v": 251, "ts": 1757649600100, "q": "good" }
]}
```

- `v`: number | string | boolean
- `ts`: epoch 밀리초
- `q`: `"good" | "bad"`. 소스 연결이 끊긴 태그는 `"bad"`.
  모의 생성기는 항상 `"good"` 을 보내지만 필드는 처음부터 존재한다
  (나중에 추가하면 클라이언트를 전부 고쳐야 하므로).

재접속: 연결이 끊기면 클라이언트가 3초 간격으로 재시도하고, 재접속에
성공하면 서버가 스냅샷을 다시 보낸다. 클라이언트는 스냅샷을 받을 때마다
로컬 값 상태를 통째로 교체한다.

## 6. 중개서버 (packtory-hub)

Node 20 + TypeScript. `node:http` + `ws` 패키지. 웹 프레임워크를 쓰지 않는다
(엔드포인트가 2개뿐).

책임 4가지:

1. **어댑터** — 외부 소스에서 값 읽기
2. **정규화** — 전부 `{ tag, v, ts, q }` 한 형태로
3. **팬아웃** — WebSocket 구독자에게 푸시 + 마지막 값 캐시(스냅샷용)
4. **씬 서빙** — `scene.json` 읽어서 `go2rtcBase` 와 함께 반환

### 어댑터 인터페이스

```ts
interface Adapter {
  start(emit: (tag: string, v: Value, ts: number, q?: Quality) => void): Promise<void>
  stop(): Promise<void>
}
```

MVP 구현체는 `MockAdapter` 하나. 씬의 모든 태그에 대해 100ms 주기로
사인파 + 노이즈 값을 생성한다. 주기 100ms는 실제 PLC 스캔 주기(보통
100ms~1초)를 흉내낸 값이다.

확장 시 `OpcUaAdapter`, `MqttAdapter` 가 같은 인터페이스를 구현하며,
클라이언트는 아무것도 바뀌지 않는다.

### 하지 않는 것

히스토리 저장, 알람 엔진, 인증, 멀티 씬, 값 쓰기. 캐시는 마지막 값만
메모리에 들고 있는다 (스냅샷 용도).

## 7. 클라이언트

Vite + React + TypeScript + Babylon.js.

React는 **UI 패널만** 담당한다. Babylon 씬은 `useEffect` 안에서 명령형으로
생성·정리한다. 선언형 래퍼(`react-babylonjs`)는 쓰지 않는다.

### 화면

전체화면 3D 뷰 + 우측 패널 하나. 그것이 전부다.

- 3D 뷰: `ArcRotateCamera` (궤도 회전/줌), 장비 클릭 시 선택
- 우측 패널: 선택된 장비의 라벨, 태그 값 목록, CCTV 영상

### 장비 상태 표현

각 장비의 재질 색:

- `warn` 이 설정된 태그 중 하나라도 값 >= `warn` → 빨강
- 전부 미만 → 초록
- 해당 장비의 태그가 전부 `q === "bad"` → 회색

### 비디오 재생

**선택된 장비의 카메라만 재생한다.** 브라우저 하드웨어 디코더의 실용
한계가 동시 9~16 스트림이므로, 씬 전체의 카메라를 동시에 띄우지 않는다.
선택이 바뀌면 이전 스트림을 끊는다.

go2rtc가 제공하는 `video-stream.js` 웹 컴포넌트를 그대로 쓴다.
영상은 패널의 `<video>` 로만 표시하고, 3D 메시 텍스처로는 입히지 않는다
(확장 항목).

## 8. 배치

| 프로세스 | 위치 | 비고 |
|---|---|---|
| go2rtc | 현장 (OT망) | 싱글 바이너리 + yaml 설정 |
| packtory-hub | 현장 (OT망) | Node 프로세스 |
| 클라이언트 정적 파일 | packtory-hub가 서빙 | 별도 웹서버 없음 |

개발 시 실제 카메라가 없으면 MediaMTX로 동영상 파일을 루프 재생하는
로컬 RTSP 소스를 띄워 대체한다.

## 9. 범위 밖 (MVP에서 만들지 않음)

명시적으로 제외한다. 필요해지면 별도 스펙으로 다룬다.

- 씬 에디터 (드래그 배치, 저장)
- 실제 프로토콜 어댑터 (OPC-UA, Modbus, MQTT)
- glTF 에셋 카탈로그
- CAD/BIM 임포트
- H.265 트랜스코딩
- 다중 카메라 동시 타일
- 3D 메시에 영상 텍스처 입히기
- 인증, 멀티테넌시, 권한
- 히스토리 저장 및 추이 차트
- 알람 엔진
- PLC 쓰기(제어)

## 10. 확장 경로

순서대로. 각 단계는 앞 단계의 인터페이스를 바꾸지 않는다.

1. **씬 에디터** — Babylon `GizmoManager` 로 배치, 씬 JSON 저장.
   최대 미지수이므로 축이 검증된 뒤에 착수한다.
2. **실제 어댑터** — `OpcUaAdapter` 를 `Adapter` 인터페이스로 구현.
   클라이언트 무변경.
3. **glTF 에셋 카탈로그** — `asset` 필드에 파일명 허용.
4. **다중 카메라 타일** — 가시성 기반 재생 제어 정책 필요.
5. **H.265** — go2rtc 트랜스코딩 설정. 카메라당 CPU 예산 산정 필요.

## 11. 완료 기준

다음 데모 각본이 처음부터 끝까지 동작하면 MVP 완료다.

1. 브라우저로 접속하면 3D 씬에 장비 3대 이상이 보인다
2. 장비를 클릭하면 우측 패널에 라벨과 태그 값이 뜬다
3. 태그 값이 멈추지 않고 갱신된다 (갱신 지연 1초 미만)
4. 같은 패널에 해당 장비의 CCTV 라이브 영상이 뜬다 (지연 1초 미만)
5. 태그 값이 임계를 넘으면 3D 상의 해당 장비 색이 빨강으로 바뀐다
6. 다른 장비를 클릭하면 영상과 값이 그 장비 것으로 바뀐다
7. 중개서버를 재시작하면 클라이언트가 자동 재접속하고 스냅샷을 다시 받는다
