# 브라우저 확인 체크리스트 (v5 — 원인 추적)

이 프로젝트를 만든 샌드박스에는 브라우저도 jsdom도 없다. 웹에는 자동화
테스트를 쓰지 않기로 했다(스펙 결정) — 유일한 근거는 `node tools/shot.mjs
<url> <출력png> [대기ms]` 로 찍은 스크린샷을 **사람이 열어서 보는 것**이다.
허브 테스트(`cd hub && npm test`)는 서버 쪽 판정 로직(`derive.ts`)과
데이터 배선만 검증한다 — 화면에 정확히 무엇이 보이는지는 이 문서를 따라
사람이 확인해야 한다.

**v2(SVG 평면도, 층 탭)는 없어졌다.** 층은 한 화면에 동시에 보이고, 층을
고르는 탭·버튼 자체가 없다. 이 문서도 그에 맞춰 다시 썼다 — 점선
(`stroke-dasharray`)·`offset-path`/Safari 항목처럼 v2 전용 SVG 코드에
관한 내용은 전부 지웠다.

## 준비

```bash
# 1. (선택) CCTV. 실제 카메라가 없으면 go2rtc.yaml 옆에 sample.mp4 (H.264 mp4
#    파일 아무거나) 를 직접 넣어야 한다 — 저장소에는 영상 파일이 없다.
#    go2rtc 가 없으면 모달의 영상 자리에 "영상 컴포넌트를 못 불러왔다" 오류가
#    뜬다 — 그 자체는 정상 동작이다(아래 7번 참조).
go2rtc -c go2rtc.yaml

# 2. 웹 빌드 + 허브 기동 (단일 프로세스, http://localhost:8080)
cd web && npm install && npm run build
cd ../hub && npm install && npm run serve
```

브라우저에서 `http://localhost:8080` 을 연다.

모의 데이터는 이제 구간 연결을 따라 흐르고, 막힘과 도크 휴무를 120초마다
시드(`MOCK_SEED`, 기본 1)로 새로 뽑는다. 작은 씬(`scene.json`)은
conv-1 → lift-1 → conv-3 → conv-5 체인이라, 가운데가 막히면 위쪽이 빨강,
아래쪽이 회색이 된다. 어느 구간이 언제 막히는지는 시드에 달렸다 — 몇 분
지켜보면 빨강과 회색이 나란히 뜨는 장면이 온다. **아래 v3 항목들이 conv-3·
conv-5 를 콕 집어 말하는 곳은 "막힌 구간"·"굶은 구간" 으로 읽는다** — 옛
고정 각본(conv-3 은 30~90초, conv-5 는 40~95초)은 없어졌다.

## 최우선 — 엔진마다 다르게 동작할 수 있는 것

Babylon 은 WebGL 로 렌더링한다. SVG 시대에는 없던 종류의 크로스브라우저
위험이 둘 있다 — 이번 점검(헤드리스 Chrome/Chromium)에서는 확인했지만,
**다른 브라우저·GPU 조합에서는 재확인이 필요하다.**

### A. 정사영 카메라가 브라우저마다 같게 보이는가

카메라는 `web/src/viewer/camera.ts` 에서 `ArcRotateCamera` 를
`Camera.ORTHOGRAPHIC_CAMERA` 모드로 고정하고 `beta = 0.9553`(진짜
아이소메트릭 각, 35.26°)로 못 바꾸게 잠가 뒀다. 이 각도·비율 계산은
WebGL 의 정사영 투영 행렬에 의존하는데, WebGL1/WebGL2 경로 선택이나
GPU 드라이버 차이로 `devicePixelRatio`/뷰포트 계산이 미묘하게 달라질
가능성이 있다. **확인:** 같은 씬을 Chrome·Firefox·(가능하면) Safari에서
나란히 찍어, 박스·원통의 마름모 윤곽 각도와 화면을 채우는 비율이
같은지 본다. 다르면 `applyZoom()`(`camera.ts`)의 `canvas.clientWidth/
clientHeight` 픽셀 비율 계산을 의심한다.

### B. 반투명 바닥판 너머로 아래층이 비치는가

`web/src/viewer/build.ts` 의 구역 바닥판(`slabMat.alpha = 0.25`)이
"층이 동시에 보인다"를 실현하는 핵심 장치다 — 2F 바닥판이 반투명해야
1F 설비가 비쳐 보인다. 알파 블렌딩 정렬(뒤에서 앞으로 그리는 순서)은
WebGL 구현마다 미묘하게 다를 수 있어, 드물게 반투명 물체끼리 겹치는
순서가 뒤집힐 수 있다. **확인:** 기본 뷰에서 2F 바닥판 너머로 1F 의
`입고 이송`·`수직반송기 1` 이 흐릿하게 비쳐 보이는지, 회전 버튼(⟲/⟳)
으로 네 모서리를 돌아가며 봐도 순서가 안 뒤집히는지 확인한다.

## 완료 기준 11개 (스펙 9장, 순서대로)

### 1. 접속하면 부지 전체가 한 화면에, 층이 동시에 보인다

`http://localhost:8080` 을 처음 연다. **보여야 함:** 층을 고르는 탭이나
버튼이 **없다.** 반투명한 1F·2F 바닥판이 비스듬히(아이소메트릭) 겹쳐
보이고, 1F 의 적재기·입고 이송·수직반송기와 2F 의 충전기·캡퍼·포장기·
충전 이송·포장 이송이 **동시에 한 화면**에 들어온다. 화면을 조작하지
않아도 전체 부지가 잘리지 않고 다 보인다. **틀렸으면 의심:**
`web/src/viewer/coords.ts` 의 `sceneBounds`(카메라 fit 계산의 기준),
`camera.ts` 의 `fit` 산식.

### 2. 가동 중인 구간에 물건이 흐르고 신호등이 초록이다

기본 화면에서 지켜본다. **보여야 함:** 각 구간 끝에 선 기둥 위 구슬
(andon)이 초록이다. 정지 중인 구간이 하나도 없을 때 상단에는 "정상 가동"
한 줄만 뜬다. **틀렸으면 의심:** `web/src/viewer/andon.ts` 의 `LAMP`
색상표.

**물건 사슬은 대부분의 시점에는 안 보인다 — 그게 정상이다.** 목 어댑터
(`hub/src/adapters/mock.ts`)는 정상 구간에서 `in` 과 `out` 을 같은
속도로 움직이므로 `wip`(재공)가 늘 0~1 에 머문다. 벨트가 거의 항상
비어 있는 채로 초록불이 도는 것이 v3 데모의 정상 장면이다. 상자가
줄지어 이동하는 장면을 실제로 보려면 conv-3(충전 이송)이 막혔다가
풀리는 **90~120초 구간**(위 "준비" 참조)을 본다 — 적체를
`DRAIN_FACTOR` 배로 배출하는 동안에만 벨트가 상자로 찬 채 흐른다.
**틀렸으면 의심:** `web/src/viewer/flow.ts` 의 `onFrame`(phase 전진 조건).

### 3. `conv-3.out` 이 멈추면 `stallSec` 뒤 신호등이 빨강 점멸하고, 물건이 꽉 찬 채 얼어붙는다

2층의 "충전 이송"(conv-3)을 40~90초 구간에 지켜본다(위 "준비" 참조).
**보여야 함:** conv-3 끝의 andon 이 빨강으로 바뀌고 1Hz 로 깜빡인다
(`andon.ts` 의 `LAMP.stalled.blinkHz = 1` — 밝은 빨강과 어두운 빨강을
매초 오간다). 벨트 위 물건 상자들은 capacity(12개)만큼 빽빽이 들어차
있고 **더는 움직이지 않는다** — 여러 장을 시차를 두고 찍어도 상자
배치가 그대로다(`flow.ts` 의 "멈춘 구간은 위상을 안 올린다" 주석대로).
구간 끝에는 `+N`(capacity 초과분) 숫자가 표시된다. **틀렸으면 의심:**
점멸이 안 됨 → `andon.ts` 의 `onFrame`. 물건이 계속 움직임 → `flow.ts`
의 `state !== "running"` 가드가 빠졌는지 확인.

### 4. 상단에 `충전부 충전 이송 정지 0:12` 칩이 뜨고 초가 올라간다

3번과 같은 창에서 상단 알림 막대를 본다. **보여야 함:** `⚠ 충전부 충전
이송 정지 0:26` 형태의 빨간 테두리 칩이 뜨고, 시간을 두고 다시 보면 그
숫자가 실제 경과 시간만큼 올라가 있다(예: 19초 뒤 다시 보면 `0:44`
근처). **틀렸으면 의심:** `web/src/AlertBar.tsx`, `web/src/state.ts` 의
`formatStall`.

### 5. 카메라를 움직이지 않아도 다른 층 신호등이 빨개지는 것이 보인다

기본 화면(카메라 조작 없음)을 열어 두고 conv-3 이 막히는 시점(40초)을
그냥 지켜본다. **보여야 함:** 회전·팬·줌 버튼을 하나도 누르지 않았는데
2F 의 conv-3 andon 만 초록에서 빨강으로 바뀐다 — v2 처럼 "다른 층 탭이
빨개진다"는 장치 자체가 필요 없다. 층이 애초에 한 화면에 다 보이기
때문에 **그냥 보인다.** **틀렸으면 의심:** 이 항목은 1번이 맞으면
구조적으로 따라온다 — 안 보이면 먼저 1번(층이 동시에 보이는지)을 다시
확인한다.

### 6. 칩을 누르면 카메라가 그 구간으로 이동한다

정지 칩이 뜬 상태에서 그 칩을 클릭한다. **보여야 함:** 화면이 팬+줌
애니메이션(약 400ms)으로 그 구간이 화면 중앙 부근에 크게 보이도록
움직인다. 이동 후에도 마름모 기울기(아이소메트릭 각)는 그대로다 —
비스듬해지거나 위에서 내려다보는 각으로 안 바뀐다. 이미 가까이 본
상태에서 눌러도 더 멀어지지 않는다(줌은 목표 줌보다 가까우면 유지).
같은 칩을 다시 눌러도(이미 그 자리를 보고 있어도) 다시 그 위치로
이동한다. **틀렸으면 의심:** `web/src/App.tsx` 의 `goTo`, `camera.ts`
의 `flyTo`(팬+줌을 같은 애니메이션으로 묶는지 — `camera.target` 을
직접 대입하면 기울기가 오염된다, 이번 계획에서 실제로 겪은 버그다).

### 7. 구간을 클릭하면 `in`/`out`/`wip`/정지시간과 CCTV 자리가 뜬다

정지 여부와 무관한 구간(예: 항상 도는 conv-1, "입고 이송")을 클릭한다.
**보여야 함:** 모달이 뜨고 제목(구간 이름)과 소속 구역, `상태`/`누적
입고`/`누적 출고`/`구간 내 재공(WIP)`/`정지 시간` 다섯 행이 표로
뜬다. 그 구간이 속한 구역에 카메라가 있으면 영상 자리가 있다(go2rtc가
없으면 "영상 컴포넌트를 못 불러왔다" 오류 문구가 뜨는 게 정상 — 그
문구 자체가 뜨는지가 확인 대상이다). 지연은 go2rtc 가 떠 있을 때만
의미가 있다(1초 미만). **틀렸으면 의심:** `web/src/Modal.tsx`,
`web/src/viewer/pick.ts`(피킹 — `Culling/ray` 사이드이펙트 임포트가
빠지면 클릭이 조용히 죽는다, 이번 계획에서 실제로 겪은 버그다).

### 8. 굶어서 비워진 구간은 신호등이 꺼진 채 비어 있고, 칩이 뜨지 않는다. 정지 구간과 나란히 한 화면에 보인다

**이 설계의 시험지 중 하나다.** 위 "준비"의 50~90초 창을 지켜본다.
**보여야 하는 것(구체적으로, 합격 장면):** 같은 화면에 conv-3(충전
이송)은 **빨강 점멸 + 꽉 찬 벨트**로 멈춰 있고, 동시에 conv-5(포장
이송)는 **어둡게 꺼진(회색) andon + 아무 물건도 없는 빈 벨트**로 떠
있다. 하나는 사고(빨강), 하나는 정상(회색) — 색뿐 아니라 물건의 유무
(꽉 참 vs 텅 빔)로도 구별돼야 한다. 상단 알림 막대에는 conv-3 칩
**하나만** 있고 conv-5 칩은 없다. 95초가 지나면 conv-5 가 곧바로(1초
이내) 초록으로 돌아와 다시 물건이 흐른다. **틀렸으면 의심:** conv-5 가
계속 초록이면 `hub/src/adapters/mock.ts` 의 `STARVE_PLAN`/`isStarved`.
conv-5 가 회색 대신 빨강이면 `wOut` 클램프(`if (wOut > backlog)`)가
빠져 WIP 가 0 으로 안 떨어진 것이다. conv-5 에 칩이 뜨면 `AlertBar.tsx`
의 필터가 `idle` 까지 잡고 있는 것이다(`stalled` 만 잡아야 한다).

### 9. 브라우저를 새로 열어도 정지 시간이 이어서 맞게 나온다

**이 설계의 나머지 시험지다.** conv-3 이 막힌 상태(40~90초)에서 새
탭(또는 새 브라우저 창)으로 같은 주소를 연다. **보여야 함:** 새로 연
탭에 뜨는 칩의 정지 시간이 원래 탭과 초 단위로 거의 같다(수백ms 오차는
정상). `stallMs` 는 허브가 서버 시계로 계산해 매 스냅샷에 실어 보내므로,
클라이언트가 언제 연결했는지와 무관하게 실제 경과 시간이 나와야 한다.
하나는 `0:45`인데 다른 하나가 `0:03`이면 실패다. **틀렸으면 의심:**
브라우저 쪽에서 `stallMs` 를 직접 계산하는 코드가 있는지 찾는다(있으면
안 된다 — `web/src/state.ts` 의 `segStallMs` 는 서버가 보낸
`{seg.id}.stallMs` 태그를 그대로 읽기만 해야 한다).

### 10. 리프트가 층 사이 관으로 보이고, 클릭하면 모달이 뜬다

1F 의 lift-1("수직반송기 1")을 찾는다. 출발점에서 수직으로 올라간 뒤
도착 층에서 가로로 꺾이는 기둥 모양이다(사선 하나로 잇지 않는다 —
층을 있는다는 게 눈에 읽히도록 일부러 이렇게 만들었다). 이 기둥이나
그 위의 andon 구슬을 클릭한다. **보여야 함:** 다른 구간과 똑같은 모달
(제목 `수직반송기 1`, `상태`/`누적 입고`/`누적 출고`/`WIP`/`정지 시간`
표)이 뜬다. v2 처럼 클릭해서 층이 전환되는 동작은 없다 — 층은 이미
동시에 보이므로 그럴 필요가 없다. **틀렸으면 의심:**
`web/src/viewer/coords.ts` 의 `segmentPoints`(리프트 분기),
`web/src/viewer/pick.ts` 의 `PRIORITY`(andon 클릭이 `segment` 선택으로
매핑되는지).

### 11. 허브를 재시작하면 자동 재접속한다

브라우저를 열어둔 채로 허브 터미널에서 `Ctrl+C` 로 껐다가 `npm run
serve` 로 다시 띄운다. **보여야 함:** 화면 상단에 잠깐 "서버와 끊김 —
재접속 중" 배너가 뜨고, 몇 초 안에 사라지며 화면이 다시 값을 받아
움직인다. 페이지를 수동으로 새로고침할 필요가 없다. (허브가 재시작되면
카운터가 0부터 다시 시작하므로 WIP 등 수치 자체는 리셋된다 — 이건
정상이다. "자동 재접속"은 "화면이 스스로 다시 살아난다"는 뜻이지
"숫자가 재시작 전후로 연속된다"는 뜻이 아니다 — 9번과 혼동하지 않는다,
9번은 *허브를 안 껐을 때* 같은 정지가 이어서 보이는지를 묻는다.)
**틀렸으면 의심:** `web/src/useValues.ts` 의 재연결 타이머
(`RECONNECT_MS`, 3초).

## 알려진 한계 (일부러 미룬 것)

- **`sceneBounds` 가 `min.y` 를 0 으로 고정한다.** 지하층(음수
  elevation)이 있는 씬에서는 초기 전체보기가 위로 살짝 치우치고
  세로로 타이트해 보일 수 있다 — 렌더가 잘리지는 않는다.
- **캔버스 크기가 `window` resize 없이 바뀌면 줌이 다시 안 맞는다.**
  사이드 패널을 여닫는 등으로 뷰어의 CSS 크기만 바뀌는 경우
  `ResizeObserver` 를 안 쓰므로 반영되지 않는다.
- **라벨끼리 겹칠 수 있다.** 충돌 회피 배치가 없다 — 스펙 요구가
  아니고, 줌해서 밀도를 낮추는 것이 이 설계가 고른 답이다.
- **데모에서는 "가동 = 물건이 흐른다" 를 정상 상태로는 못 본다.**
  `hub/src/adapters/mock.ts` 가 정상 구간에서 `in`/`out` 을 같은
  속도로 움직여 `wip` 가 0~1 에 머문다 — 색을 빼면 가동과 대기가
  화면(빈 벨트)으로는 구별되지 않는다. 정지 vs 대기(스펙의 핵심
  구분)는 멀쩡하다 — 정지 구간은 꽉 찬 벨트로 얼어붙는다. 이 브랜치는
  목 어댑터(허브, v2 부터 존재)를 건드리지 않는다 — 기준 8 의 타이밍이
  전부 다시 계산돼야 하기 때문이다.
- **`+N` 이 `flow.ts` 의 `MAX_ITEMS = 60` 을 모른다.** 어떤 구간의
  capacity 가 60 을 넘으면 `+N` 이 실제보다 적게 나온다. 현재
  `scene.json` 의 구간은 전부 capacity 24 이하라 해당 없다.
- **씬 검증 규칙 7 의 함정.** 층 `order` 가 중복이고 둘 다 `elevation`
  을 생략하면 에러가 난다. 오늘 씬에는 그런 용례가 없다.
- **Safari 를 못 봤다.** 이 점검은 macOS 가 없는 환경에서 했다 — WSL
  에서 Windows 쪽 Chrome 헤드리스로만 확인했다. 위 "최우선 A/B" 두
  항목은 Safari 에서 재확인이 필요하다.
