# 브라우저 확인 체크리스트

이 프로젝트를 만든 샌드박스에는 브라우저도 jsdom도 없다. 그래서 스펙
11장의 완료 기준 12개 중 화면에 실제로 렌더링되는 부분은 코드로 검증할
수 없었다 — 자동화 테스트(허브 37개)와 `curl`/WebSocket 스크립트로 서버
쪽은 확인했지만, "화면에 정확히 무엇이 보이는가"는 사람이 브라우저 앞에
앉아 이 문서를 따라가며 확인해야 한다.

## 준비

```bash
# 1. (선택) CCTV. 실제 카메라가 없으면 go2rtc.yaml 옆에 sample.mp4 (H.264 mp4
#    파일 아무거나) 를 직접 넣어야 한다 — 저장소에는 영상 파일이 없다.
go2rtc -c go2rtc.yaml

# 2. 웹 빌드 + 허브 기동 (단일 프로세스, http://localhost:8080)
cd web && npm install && npm run build
cd ../hub && npm install && npm run serve
```

브라우저에서 `http://localhost:8080` 을 연다. **탭을 연 시각을 적어두면**
아래 conv-3·conv-5 관련 항목의 타이밍을 맞추기 쉽다.

conv-3(충전 이송)은 120초 주기로 반복된다: 0~30초 정상 → 30~90초 out 정지
(막힘 시작) → 90~120초 배출(적체 해소) → 120~150초 정상 → 150초에 다음
막힘 시작. 다만 화면이 빨강으로 바뀌는 건 막힘 시작 30초가 아니라
`stallSec`(10초) 유예가 지난 **40초** 시점부터다(`derive.ts`: out이
안 바뀐 지 10초가 지나야 stalled로 판정한다) — 30~40초 사이는 아직
초록으로 보이는 게 정상이다. 아래 3·4번 항목은 40~90초 사이에, 9번은
정지 중(40~90초)에 확인해야 한다.

같은 120초 주기 안에서 conv-5(포장 이송)는 40~95초에 굶는다(`in` 이
멈춘다) — 재공이 빠지고 `out` 도 스스로 멎어 idle(회색)이 된다. 화면에는
`stallSec` 유예 때문에 **50초**부터 회색으로 보이고, 95초에 `in` 이
재개되면 거의 즉시(약 95.5초) 다시 초록으로 돌아온다. 그 결과 **50~90초
사이**는 conv-3(빨강, 꽉 참)과 conv-5(회색, 텅 빔)가 같은 2층 화면에
동시에 떠 있다 — 이게 완료 기준 8 의 합격 장면이다. (허브·derive를 실제
코드 그대로 260초 시뮬레이션해 확인한 값이다: 50.0s에 conv-5 idle 진입,
90.0s에 conv-3 running 복귀, 두 번째 주기(170~210s)에도 동일하게
반복됨 — 아래 8번 항목 참조.)

## 최우선 — 한 번도 실행된 적 없는 코드 (여기부터 확인)

아래 두 항목은 이번 태스크 이전에는 **한 번도 실제로 구동되지 않은
코드 경로**다. 나머지 10개 항목보다 결함이 있을 가능성이 훨씬 높다.

### A. 칩 클릭 → 층 전환 + 지도 이동 (완료 기준 6)

`Map.tsx` 의 `lastPan` 이중 `useEffect` 는 Task 6 이 만들었지만 Task 9
전까지 `App.tsx` 가 `panTo={null}` 을 하드코딩해서 죽은 코드였다. 실제로
구동되는 것은 이번이 처음이다.

**조작:**
1. 층 탭에서 `1F` 를 클릭해 1층 화면으로 이동한다.
2. conv-3 이 막혀 상단에 `⚠ 충전부 충전 이송 정지 0:xx` 칩이 뜰 때까지
   기다린다 (허브 기동 후 40~90초 사이, 못 봤으면 새로고침 없이 계속
   기다리거나 120초 뒤 다음 주기를 기다린다).
3. 그 칩을 클릭한다.

**보여야 하는 것 (구체적으로):**
- 왼쪽 층 탭 목록에서 `2F` 탭이 파란 강조(`current`, 배경색이 바뀜)로
  바뀐다 — `1F` 탭은 강조가 풀린다.
- 지도가 2층 전체 보기가 **아니라** conv-3(충전 이송) 구간이 화면
  가운데 근처로 오도록 확대/이동된 상태로 바뀐다. 층만 바뀌고 지도가
  2층 전체 보기 그대로 멈춰 있으면 실패다.
- 같은 칩을 (이미 2F 를 보고 있는 상태에서) **한 번 더** 클릭해도 지도가
  다시 그 위치로 이동한다 (아무 반응 없음 = 실패).

**틀렸을 때 의심할 곳:**
- 층만 바뀌고 이동이 안 됨 → `web/src/Map.tsx` 의 두 `useEffect` 순서.
  "층이 바뀌면 전체보기로" effect 가 "이상 칩 이동" effect 보다 나중에
  실행되며 `lastPan.current` 갱신 전에 먼저 조건을 봐서 되돌리기 때문일
  수 있다 (파일 안 주석에 이 순서 의존성이 적혀 있다).
- 같은 칩 재클릭이 무반응 → `App.tsx` 의 `nonceRef`/`goTo` 또는 `Map.tsx`
  의 `lastPan.current` 비교 로직에서 nonce 갱신이 안 되고 있을 가능성.
- 지도가 엉뚱한 위치로 감 → `toSvgY` 좌표 변환(Y축 반전)이 `panTo` 계산에
  누락됐는지 확인 (`Map.tsx` 의 `setVb` 안 `toSvgY(panTo.y, b)`).

### B. Safari 에서 점이 `.rail` 경로 위에 정확히 붙는가 (완료 기준 1, 3)

`Segment.tsx` 의 흐름 점(`<circle className="item">`)은 CSS
`offset-path: path("...")` 로 SVG `<circle>` 을 움직인다. 이 기능이 걸린
caniuse 플래그(`css-motion-paths`)는 **일반** 지원 플래그이지 "SVG 요소에
적용했을 때" 전용 플래그가 아니다. WebKit 은 이 영역에서 역사적으로
지원이 늦었고, SVG 자식 요소에 `offset-path`/`transform` 을 걸 때
좌표계 기준(reference box)을 엔진마다 다르게 해석해온 전례가 있다.

**조작:**
1. Safari(macOS 또는 iOS)에서 앱을 연다. Chrome/Firefox 는 대조군으로만
   쓴다 — WebKit 이 아니면 이 항목의 의미가 없다.
2. 항상 흐르고 있는 conv-1(입고 이송, 1F)을 지도 확대(`+` 버튼 또는
   휠 스크롤)로 여러 단계 확대한다.

**보여야 하는 것 (구체적으로):**
- 작은 점 하나하나의 **중심**이 정확히 레일(구간 선) 위에 있어야 한다.
  Chrome/Firefox 와 나란히 놓고 비교했을 때 점이 선의 위·아래·옆으로
  치우쳐 있으면 안 된다.
- 확대할수록 어긋남이 있다면 더 커 보인다 (점 반지름이 고정된 SVG
  단위이므로) — 전체보기와 최대 확대, 두 배율에서 모두 확인한다.

**틀렸을 때 의심할 곳:**
- 점이 레일에서 일정 거리 벗어나 있거나(위치 오프셋), 지도 좌측 상단
  등 완전히 엉뚱한 곳에서 움직인다 → `web/src/Segment.tsx` 의 `<circle>`
  에 `cx`/`cy` 가 없는 것은 의도적이다(원의 로컬 원점을 경로 좌표계와
  일치시키기 위함). Safari 가 `offset-path` 의 기준 상자(reference box)를
  다르게 해석하는 것이 원인일 가능성이 높다 — `transform-box` 를 명시
  (`view-box` 또는 `fill-box`)하면 고칠 수 있는지 실험해본다.
- 점 자체가 전혀 안 움직인다 → 이건 위치 문제가 아니라 Safari 버전이
  `offset-path` 자체를 지원하지 않는 것이다. Safari 버전을 확인한다.

## 나머지 완료 기준 (스펙 11장, 순서대로)

### 1. 2층 평면도에 구역·장비·구간이 뜨고 가동 구간에 점이 흐른다
탭을 연 직후(40초 전) `2F` 를 클릭한다 — 40~95초 사이에 보면 conv-5 가
아래 8번 각본 때문에 잠깐 회색으로 비어 보일 수 있는데, 그건 정상이지
이 항목의 실패가 아니다. **보여야 함:** "충전부"·"포장부" 배경 사각형,
그 안에 "충전기 1"·"캡퍼 1"·"포장기 1" 회색 사각형, conv-3·conv-5 초록
선 위로 작은 점들이 한 방향으로 흐름. **틀렸으면 의심:** `Map.tsx` 의
`sections`/`equipment` 필터링(`floorId` 매칭), `Segment.tsx` 의 `flat`
필터.

### 2. 층 탭 2개에 상태 배지, 누르면 그 층 지도로 바뀐다
왼쪽에 `1F`/`2F` 두 탭이 보이고 각각 ●/▲/○/? 배지 + "가동"/"정지"/"대기"/
"불명" 글자가 있다. 클릭하면 지도가 그 층으로 바뀐다 (이동 없이 그
층 전체 보기). **틀렸으면 의심:** `FloorTabs.tsx`.

### 3. 40초쯤 conv-3 이 빨강 점선으로 바뀌고 점이 얼어붙고 개수가 늘어난다
2층 화면에서 지켜본다. **보여야 함(구체적으로):** 40초 무렵 conv-3 선이
빨강 + 점선(`stroke-dasharray`)으로 바뀌고 1초 주기로 깜빡인다. 점들은
각자 자리에서 멈춘다(한 점으로 뭉치지 않는다). 구간 끝에 `+N` 텍스트가
뜨고 숫자가 계속 커진다 (막힘 시작 후 최대 약 `+108` 까지, 90초 시점).
**90초가 지나면(이번 태스크에서 고친 부분):** 점선이 풀리고 초록으로
돌아오며 `+N` 이 서서히 줄어들다 사라진다 — 120초 시점쯤에는 완전히
사라져야 한다. `+108` 이 안 줄고 계속 남아있으면 실패다 (이월 1 회귀).
**틀렸으면 의심:** 점선/깜빡임 → `styles.css` 의 `[data-state="stalled"]`
규칙. `+N` 이 안 줄어듦 → `hub/src/adapters/mock.ts` 의 `DRAIN_FACTOR`
로직이 되돌아갔는지 확인.

### 4. 상단에 `충전부 충전 이송 정지 0:12` 칩이 뜨고 초가 올라간다
막힘 중 상단 막대에 빨간 테두리 알약(칩)이 뜨고 `⚠ 충전부 충전 이송 정지
0:05`, `0:06`... 처럼 초가 1초 단위로 올라간다. **틀렸으면 의심:**
`AlertBar.tsx`, `Segment.tsx` 의 `formatStall`.

### 5. 1층을 보고 있어도 2F 탭이 빨개진다
1F 화면에서 conv-3 이 막힌 동안 왼쪽 `2F` 탭 테두리가 빨갛게 바뀌고
배지가 ▲(빨강)로 바뀐다. **틀렸으면 의심:** `FloorTabs.tsx` 의
`floorState` (현재 보고 있는 층과 무관하게 전체 구간을 본다).

### 6. 칩을 누르면 2층으로 전환되고 지도가 그 구간으로 옮겨간다
→ 위 "최우선 A" 항목 참조. 여기서 다시 확인할 필요 없다.

### 7. 구간을 클릭하면 수치와 CCTV 라이브가 뜬다 (지연 1초 미만)
2층에서 conv-3 또는 conv-5 를 클릭 (막혀있지 않아도 됨). **보여야 함:**
모달이 뜨고 상태/누적 입고/누적 출고/WIP/정지시간 표가 나오고, "충전기
상부"·"캡퍼 측면" 탭과 함께 영상이 재생된다. 영상이 실시간에 가깝게
움직여야 한다(체감 지연 1초 미만 — 카메라 앞에 초시계나 휴대폰 시계를
두고 화면 속 초침과 실제 초침 차이를 재면 정확하다). **틀렸으면 의심:** go2rtc 가 안 떠
있거나 `sample.mp4` 가 없음 → "영상 컴포넌트를 못 불러왔다" 오류 문구
확인, `Modal.tsx` 의 `useGo2rtcScript`.

### 8. 빈 구간은 회색 대기로 남고 칩이 안 뜬다
`hub/src/adapters/mock.ts` 의 `STARVE_PLAN` 이 conv-5(포장 이송)를
40~95초에 굶긴다(`in` 정지) — 이번에 새로 추가된, 아직 실제 브라우저로
본 적은 없는 각본이다. 위 "최우선" 두 항목만큼은 아니지만 처음 확인할
때는 주의 깊게 볼 가치가 있다.

**조작:** 2층 화면을 띄워두고 50~90초 구간을 지켜본다(정확한 시각은
탭을 연 시점 기준 — 위 "준비"의 타임라인 참조).

**보여야 하는 것(구체적으로, 이게 이 항목의 합격 장면이다):**
- **50초 무렵부터 90초까지**, 같은 2층 화면에 **conv-3 은 빨강 점선으로
  꽉 찬 채(`+N` 이 두 자리로 커진 상태) 멈춰 있고, 동시에 conv-5 는
  회색 실선에 점이 하나도 없이 텅 빈 채** 떠 있어야 한다. 하나는 사고
  (빨강, WIP 가 가득 참), 하나는 정상(회색, WIP 0) — 이 둘이 **나란히**
  보이는 것 자체가 합격 신호다. 색만 다른 게 아니라 점의 유무(꽉 참 vs
  텅 빔)로도 구별돼야 한다.
- conv-5 위에는 경고 칩이 뜨지 않는다(상단 알림 막대에는 conv-3 칩만
  있어야 한다) — `idle` 은 정상이라 칩 대상이 아니다.
- 95초가 지나면 conv-5 가 곧바로(1초 이내) 초록으로 돌아와 다시 점이
  흐른다.
- **틀렸으면 의심:** conv-5 가 계속 초록이면(회색으로 안 바뀌면)
  `mock.ts` 의 `isStarved`/`STARVE_PLAN` 이 안 걸리는지 확인. conv-5 가
  회색 대신 빨강(점선)으로 보이면 `in` 은 멈췄는데 `out` 이 못 따라가
  WIP 가 0 이 아닌 채로 남은 것 — `wOut` 클램프(`if (wOut > backlog)`)
  가 빠졌는지 본다.

**시뮬레이션으로 미리 확인한 타이밍**(`MockAdapter`+`derive` 실제 코드를
260초 수동 시계로 돌려 확인, 브라우저 확인 전 참고용):
```
t=39.5s   conv-3: running -> stalled  (wip=20)
t=50.0s   conv-5: running -> idle     (wip=0)
t=90.0s   conv-3: stalled -> running  (wip=120)
t=95.5s   conv-5: idle -> running     (wip=0)
겹침 구간: 50s~90s (1주기), 170s~210s (2주기) — 두 번째 주기도 동일하게 반복됨
```

### 9. 브라우저를 새로 열어도 정지 시간이 이어서 맞다
**서버 쪽은 이미 확인함:** 서로 다른 시각에 새로 연 WebSocket 연결 두
개에서 conv-3.stallMs 가 실제 경과 시간만큼만 증가하고 리셋되지 않는
것을 스크립트로 확인했다(5초 간격 재연결 시 stallMs 증가분이 정확히
~5000ms). **브라우저에서 추가로 확인할 것:** conv-3 이 막힌 상태에서
같은 주소로 새 탭을 하나 더 연다. 두 탭의 칩에 적힌 정지 시간(`0:xx`)이
서로 초 단위로 거의 같아야 한다(수백ms 오차는 정상). 하나는 `0:45`인데
다른 하나가 `0:03`이면 실패다. **틀렸으면 의심:** 브라우저에서 `stallMs`
를 직접 계산하는 코드가 있는지 찾는다(있으면 안 된다 — 서버가 보내는
`{seg.id}.stallMs` 태그를 그대로 표시만 해야 한다).

### 10. 리프트 마커를 클릭하면 상대 층으로 전환된다
1층 또는 2층 지도에서 세모(▲/▼) 화살표가 있는 원형 마커(lift-1,
수직반송기)를 클릭한다. **보여야 함:** 모달이 뜨지 않고, 대신 층 탭이
반대쪽 층(1층에서 눌렀으면 2F, 2층에서 눌렀으면 1F)으로 바뀌며 그 층
지도가 보인다. 리프트의 상태·WIP 수치는 모달 없이도 마커 옆 라벨
(`2F · 3` 형식)과 마커에 마우스를 올렸을 때 뜨는 툴팁으로 이미 보인다.
**틀렸으면 의심:** `Segment.tsx` 의 `lifts.map(...)` 블록 `onClick` 이
`onSelect` 를 부르는지(그러면 모달이 뜬다 — 스펙 8장·완료 기준 10 위반),
`onFloorChange` 를 부르는지 확인한다.

### 11. 허브를 재시작하면 자동 재접속하고 값이 이어진다
브라우저를 열어둔 채로 허브 터미널에서 `Ctrl+C` 로 껐다가 `npm run
serve` 로 다시 띄운다. **보여야 함:** 화면 상단에 잠깐 "서버와 끊김 —
재접속 중" 배너가 뜨고, 몇 초 안에 사라지며 지도가 다시 값을 받아
움직인다. 페이지를 수동으로 새로고침할 필요가 없어야 한다. (허브가
재시작되면 카운터가 0부터 다시 시작하므로 WIP 등 수치 자체는 리셋된다 —
이건 정상이다. "값이 이어진다"는 "화면이 자동으로 다시 살아난다"는
뜻이지 "숫자가 재시작 전후로 연속된다"는 뜻이 아니다.) **틀렸으면
의심:** `web/src/useValues.ts` 의 재연결 타이머(`RECONNECT_MS`).

### 12. 포장부를 클릭하면 영상 자리 없이 수치만 뜬다
2층에서 "포장부" 배경(또는 포장기 1, 또는 conv-5)을 클릭한다. **보여야
함:** 모달에 표만 있고 영상 영역 자체가 없다(빈 칸도 아니고 아예 없어야
함 — "포장부" 섹션은 `scene.json` 에 카메라가 없다). **틀렸으면 의심:**
`Modal.tsx` 의 `cams.length > 0` 분기.
